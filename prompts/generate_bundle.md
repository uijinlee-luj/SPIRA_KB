# 생성 프롬프트 — 물건 묶음 (v1)

> 담당: U. 기준 문서 5-1절. 수정 이력은 이 파일의 커밋 기록으로 남는다.
> 실행 스크립트가 `{input_path}`, `{output_path}`를 채워서 에이전트에게 준다.

---

당신은 장보기 데이터 작성자입니다. `{input_path}` 파일을 읽고, 결과를 `{output_path}`에 JSON으로 쓰세요.

## 할 일

작업 파일의 `goals`마다, 그 **목적(intent)** 으로 그 **가구(household_types)** 가 온라인으로 주문할 법한 **물건 묶음**을 하나씩 만드세요.

- 묶음은 물건 **2~6개**입니다.
- 목적의 **정의(definition)에 적힌 구분 단서**가 묶음에 드러나야 합니다. 예를 들어 "아이 생일 파티"라면 아이용 파티 소품이, "어른 생일 축하"라면 아이용 소품 없이 케이크·꽃 같은 물건이 들어가야 합니다.
- 정의에 "중 2개 이상"이라고 적힌 목적(계절 · 옷 · 이불 교체 등)은 그 신호 물건을 **2개 이상** 넣으세요.
- 그 목적이 아니면 잘 사지 않는 물건을 중심으로 고르세요. 우유 · 휴지처럼 늘 사는 물건은 넣지 마세요 (평소 장보기 물건은 나중에 따로 섞습니다).
- 같은 작업 안에서 같은 목적이 여러 번 나오면, 묶음을 서로 다르게 만드세요.

## 물건 이름 규칙

- **단순한 일반 이름**만 씁니다. 예: 딸기, 세제, 줄넘기, 케이크, 생일 초, 고깔모자
- 브랜드 · 용량 · 수량 · 수식어를 넣지 않습니다. ("○○ 유기농 딸기 500g" → 딸기)
- 2~3단어 이내로 씁니다.

## 하지 말 것

- 이야기 · 설명 · 정답을 쓰지 않습니다. 물건 이름만 씁니다.
- 스크립트를 짜서 자동으로 만들지 않습니다. 목적마다 직접 생각해서 만듭니다.
- 작업 파일에 없는 목적을 만들지 않습니다.

## 결과 형식

`{output_path}`에 아래 형식의 JSON만 씁니다. 모든 `goal_id`에 대해 하나씩 씁니다.

```json
{
  "job_id": "작업 파일의 job_id 그대로",
  "bundles": [
    { "goal_id": "A1-2_g0042", "items": ["케이크", "생일 초", "고깔모자", "답례품 봉투"] }
  ]
}
```
