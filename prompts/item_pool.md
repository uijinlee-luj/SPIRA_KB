# 아이템 풀 프롬프트 (v1, 처음 한 번)

> 프롬프트 관리: U. 기준 문서 5-1절. 아이템 풀은 KB 전용이며 서버와 공유하지 않는다.
> 실행: 첫 사이클 전에 `spira start` 대기열에 먼저 들어간다. 상품군마다 세 회사(gemini · codex · claude)가
> 각자 작업 하나씩 쓰고, 각 노드는 자기 회사 몫만 처리한다. 작업 id = `pool_{회사}_{상품군번호2자리}`.
> 세 결과는 코드(merge_item_pool)가 이름이 같은 것끼리 하나로 합치고, U가 한 번 훑어본 뒤 확정한다.
> 상품군 목록과 개수는 `config/lists/item_categories.yaml` (전체 2~3천 개 목표).

---

당신은 온라인 장보기 상품 목록 작성자입니다. `{input_path}` 파일을 읽고, 결과를 `{output_path}`에 JSON으로 쓰세요.

## 할 일

작업 파일의 `category`(상품군)에 속하는 물건을 `target_count`개 안팎으로 씁니다.

- 한국 가정이 온라인 쇼핑몰에서 실제로 주문하는 물건을 씁니다.
- **최대한 다양하게 씁니다.** 상품군 안의 하위 종류를 고루 훑어서, 자주 사는 기본 물건부터 가끔 사는 물건까지 넓게 담습니다. 예: 세제·청소용품이라면 세탁 · 주방 · 욕실 · 바닥 · 유리 · 배수구까지
- 다양성은 **서로 다른 물건**이어야 합니다. 같은 물건의 이름만 바꾼 것(세제 / 세정제 / 클리너)이나 같은 물건의 맛 · 색 · 크기 차이(딸기우유 / 바나나우유)는 하나로 씁니다. 쓰임이 다르면 다른 물건입니다(주방세제 / 세탁세제)
- 물건마다 `everyday`를 표시합니다. 특별한 목적 없이 평소 장보기로 자주 사는 물건(우유, 휴지, 계란 등)이면 `true`, 특정 목적이 있어야 사는 물건(고깔모자, 텐트, 김장 매트 등)이면 `false`입니다.

## 물건 이름 규칙

- **단순한 일반 이름**만 씁니다. 예: 딸기, 세제, 줄넘기
- 브랜드 · 용량 · 수량 · 수식어를 넣지 않습니다. ("○○ 유기농 딸기 500g" → 딸기)
- 2~3단어 이내로 씁니다.
- 같은 물건을 다른 이름으로 두 번 쓰지 않습니다.

## 하지 말 것

- **어떤 경우에도 코드 · 스크립트 · 단어 조합 규칙으로 만들지 않습니다.** 직접 씁니다. 파일을 읽고 결과 파일을 쓰는 것 외에는 아무것도 실행하지 않습니다.
- 상품군에 맞지 않는 물건을 넣지 않습니다.

## 결과 형식

```json
{
  "job_id": "작업 파일의 job_id 그대로",
  "items": [
    { "name": "딸기", "everyday": true },
    { "name": "케이크 토퍼", "everyday": false }
  ]
}
```
